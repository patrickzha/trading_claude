# 美股周频 AI 选股系统

标普500全量股票池，每周一开盘买入、周五收盘卖出的周频动量策略。用
XGBoost 做 walk-forward 训练（每周只用截止当前的历史数据重新训练，不会
用到未来信息），叠加宏观熔断、财报避让、账户级回撤熔断等风控规则。

**这份 README 会如实写明当前的验证结论，包括不利的部分。**这段开场白早期版本引用的数字（止损5%→2%时Sharpe 0.42→0.76）已经过时——后续发现生存偏差修复后全样本Sharpe实际只有约-0.05（"验证结论"第27/32条），单独的周频动量策略统计上没有站得住脚的正向edge。**目前最可信的结论和推荐配置见下面"现状总结"一节和第55-59条**：动量+价值+低波动三元组合是这次会话所有测试过的方向里证据最扎实的一个（不是"确认的新alpha"，只是"目前最站得住脚、没被证伪的候选"），已经过三段独立历史区间(2022-2026/2014-2020/2009-2014)交叉验证。**【第108-110条重要修正】2014-2020/2009-2014这两段"独立区间"直到第108条之前，一直没有做过跟2022-2026同等级别的生存偏差(纳入日期)修正——修正后动量腿Sharpe暴跌68-83%，组合层面因为等权稀释影响较小但2014-2020段依然有约30%的下修（完整系统Sharpe从1.533降到1.082）。本文档正文里第108条之前所有引用这两段绝对Sharpe/CAGR数字的条目，数值本身有不同程度的高估，方向性/相对比较结论大概率仍然成立，但绝对数字请以第108-110条的修正版为准。**【第307条第二次同类重要修正】2022-2026这段本身也中招——`default_full_results_cache.pkl`(全会话引用次数最多的2022-2026动量腿缓存，40+个测试脚本直接用它)从生成时起就没做过点位时间修正，一直到第307条才发现并修正。当前"现状总结"的旗舰配置(第276条)绝对数字已经用修正后缓存重新验证并更新(Sharpe从2.301下修到1.766)，相对比较结论(3%止损优于5%)本身经重新检验依然成立且仍统计显著。本文档正文里第307条之前所有引用`default_full_results_cache.pkl`的2022-2026绝对Sharpe/CAGR/MaxDD数字（尤其是"现状总结"里第67-276条的历史迭代过程）同样存在不同程度的高估，方向性结论大概率仍然成立，但没有逐条重新验证，详见第307条。**【第330条第三次同类修正，范围最广但幅度最小】SEC基本面数据抓取脚本(`fetch_sec_fundamentals.py`)的标签匹配逻辑有一个从最早写出来就存在的bug(优先级列表里第一个有数据的标签就用，不看后面覆盖更全的标签)，第330条发现这个bug影响96.4%的股票在P/E/P/B/ROE计算依赖的原始字段(尤其`shares_outstanding`)上数值不准确——即本文档所有引用价值腿(P/E-P/B-ROE)绝对数字的条目都受到不同程度影响，范围比前两次修正都大，但用旗舰配置头对头验证的幅度很小(+3.5%，方向是变好)，详见第330条。**用之前请先看完"现状总结"和"验证结论"两节。

## 快速开始

```bash
# 1. 装依赖（用项目自带的 .conda 环境）
.conda/bin/pip install -r requirements.txt  # 如果没有 requirements.txt，见下面依赖列表

# 2. 生成/刷新股票池（标普500成分股，一年变动不大，不用每次都跑）
.conda/bin/python3 build_sp500_universe.py

# 3. 每周实际使用：生成动量+价值+低波动三元组合的当前候选(推荐，见"现状总结")
.conda/bin/python3 generate_current_recommendations.py

# 3b. 只想看原始单一动量策略信号（不推荐单独使用，历史Sharpe约-0.05）
.conda/bin/python3 generate_weekly_signal.py

# 4. 跑历史回测（5年数据，8核并行大概30分钟）
.conda/bin/python3 backtest.py

# 5. 跑三元组合的完整历史回测(CAGR/Sharpe/真实最大回撤)
.conda/bin/python3 -c "
from combo_strategy import run_combo_strategy, print_report
# 具体用法见 combo_strategy.py 顶部的说明
"
```

依赖：`pandas numpy xgboost shap matplotlib hmmlearn statsmodels yfinance requests`

## 每周怎么用

```bash
.conda/bin/python3 generate_weekly_signal.py
```

跑完会打印这周该买哪几只、权重和仓位系数，同时追加写入
`weekly_signal_log.csv`。这份日志是唯一能验证"这套系统在实盘里到底
灵不灵"的办法——回测数字不能代替真实、事先不知道结果的记录。建议：

1. 每周一开盘前跑一次，记录信号（脚本本身不下单，要不要真的按这个操作
   是你自己的决定）。
2. 攒够至少 3-6 个月的信号后，回头对照实际走势，看实盘表现是否跟回测
   预期一致。这比继续在同一份历史数据上调参数有意义得多。

## 项目结构

**核心引擎**
- `us_stock_screener.py` — 特征工程 + XGBoost 训练/预测，`get_ai_weekly_picks()` 是核心入口
- `backtest.py` — walk-forward 回测驱动，`run_walk_forward_backtest()`；支持多进程并行（`n_workers`）
- `optimized_metrics_v4.py` — 回测报告（含样本内/外统计检验）
- `stat_validation.py` — 样本外切分 + block bootstrap 显著性检验
- `sp500_universe.json` — 标普500成分股 + GICS行业缓存（`build_sp500_universe.py` 生成）
- `fetch_sec_fundamentals.py` — 从 SEC EDGAR 拉取基本面数据，生成 `sec_fundamentals_cache.json`（带真实披露日期，无前视偏差；`use_fundamental_features` 开关用，默认关闭，见"验证结论"第10条）

**新增引擎（本轮，独立于原始动量策略）**
- `value_investing.py` — 长周期价值投资引擎，`backtest_value_strategy()`，低PE/PB+高ROE选股，SEC EDGAR基本面数据点位时间正确（见"验证结论"第38条）
- `low_vol_investing.py` — 低波动因子引擎，`backtest_low_vol_strategy()`，选trailing 60日已实现波动率最低的票（见第55条）
- `classic_momentum.py` — 经典12-1月动量因子(UMD)，跟价值因子相关性太高，未采纳，仅供参考（见第56条）
- `pairs_trading.py` — 统计套利/配对交易引擎，distance method，测试结论是标普500上无edge（见第37条）
- `combo_strategy.py` — **推荐使用**：动量+价值+低波动三元组合的统一接口，`run_combo_strategy()` / `print_report()`（见第55-58条）

**每周实盘**
- `generate_current_recommendations.py` — **推荐使用**：生成三元组合当前候选(动量本周/价值本月/低波动本月三份名单，见第59条)
- `generate_weekly_signal.py` — 只生成原始单一动量策略信号（不推荐单独使用，历史Sharpe约-0.05，见"现状总结"），写入 `weekly_signal_log.csv`

**诊断/研究工具**（不进主流程，独立跑）
- `diagnostics_granger_vix.py` — Granger 因果检验：VIX 变化是否真的领先于未来收益
- `analyze_macro_filter_contribution.py` / `analyze_circuit_breaker_legs.py` — 拆解宏观熔断规则（VIX腿/动量腿）各自的贡献
- `run_full_validation.py` / `run_sp500_backtest.py` / `run_sp500_regularized.py` / `run_sp500_ensemble.py` — 历次完整验证跑批脚本，可以参考着改

**历史遗留（不是当前代码生成的，供参考，不建议再用）**
- `candidates.csv` / `weekly_trade_plan.csv` / `weekly_momentum_picks.csv` / `low_price_momentum_picks.csv` — 更早期某个筛选流程的输出快照，跟现在的代码不是一套逻辑

## 现状总结：如果现在要实盘，该用什么（2026-08更新）

这一节是给"没空看完59条验证结论"的人看的执行摘要，如实汇总到目前为止最可信的结论，不夸大也不藏着掖着。

**周频动量策略（原始主策略）**：止损2%、RSI阈值100、新近度加权26周(默认配置)，这三条参数改进本身是真实的（三窗口+全量+独立历史区间三重验证过）。但生存偏差修复后（"验证结论"第27条），全样本Sharpe只有约-0.05（用第32条bug修复后的确定性代码算出的可信数字，不是第27条略高估的0.02），95%置信区间跨0——**这套策略单独用，统计上没有站得住脚的正向edge，只是勉强不亏钱**。逐笔诊断（第29条）显示模型预测值跟实际结果相关系数只有-0.0179，选股这一步本身没有真实的排序能力，收益主要靠止损/熔断规则做下行保护撑着。

**长周期价值投资（本轮新增）**：低PE+低PB+高ROE，月度调仓（不是最初测的半年度，半年度Sharpe被小样本高估，见第48条），CAGR跑赢SPY，但Fama-French分解显示这基本是买入了HML价值因子（第39条），策略本身的alpha不显著。

**动量+价值组合(各50%)，目前证据最扎实的选项，已经过三段独立历史区间(2022-2026/2014-2020/2009-2014)交叉验证(第51条)**：两条策略相关系数只有0.14-0.27，混合后有真实分散化效应（第45条），但"最优权重在中间"这个更具体的说法只有2/3区间成立（第53条：2009-2014是纯价值单调最优，不是中间权重最优）。三段区间、两种检验方法的完整结果：

| 区间 | 组合Sharpe(bootstrap) | 组合alpha(Fama-French) |
|---|---|---|
| 2022-2026 | 0.790, 边缘不显著(p=6.2%) | t=0.31，不显著 |
| 2014-2020 | 1.294, **显著**(p=0.0%) | t=2.49，**显著** |
| 2009-2014 | 1.376, **显著**(p=0.1%) | t=1.50，不显著 |

**bootstrap检验3段里2段显著，Fama-French检验3段里只有1段显著**——这个组合大概率能提供正的风险调整后收益（3/3期Sharpe都是正的，2/3显著），但"这部分收益有多少是已知市场/规模/价值因子解释不了的新edge"证据并不牢靠（只有1/3期站得住）。

**加第三条腿(低波动因子)之后，三元组合(动量+价值+低波动，第55条)进一步把bootstrap检验推到接近3/3显著**——是目前统计证据最强的配置。【第359条补充】低波动腿本身此前从未单独做过3段区间独立显著性检验，Cycle80补上这个空白：三段点估计全部为正(2009-2014 Sharpe=1.010独立显著、2014-2020 Sharpe=0.504接近显著、2022-2026 Sharpe=0.209不显著)，是三条腿里唯一在至少1段独立通过标准显著性检验的一条腿。但要留一个重要的警示：低波动腿跟价值腿高度相关(0.51-0.74)，这次改善一部分可能只是"变相加大了价值因子权重"，不是真正引入了新的独立信号，且这是第60个左右的候选测试，第36条的多重检验警示同样适用。试过用经典12-1月动量因子做第四条腿或替代低波动腿(第56条)，结果全面更差，不采纳，三元组合(动量+价值+低波动)维持最佳。**【第111条重要修正】三元组合的Fama-French alpha显著性此前没有单独发布过精确数字，Cycle22第111条第一次专门测了(用生存偏差修正后的动量数据)：2014-2020从表面上"显著"(修正前t=2.55)变成不显著(t=0.92，此前这一段一直是"三元组合有真正新edge"这个判断唯一的显著性支撑)，2009-2014修正后依然显著(t=2.36)。****如实调整表述：不能再说三元组合"证据比二元组合更强"，更准确的说法是"证据不支持三元组合存在无法用已知因子解释的新alpha"，分散化/风险管理价值(bootstrap检验、真实回撤压缩)依然成立，但"新edge"这个更强的表述需要收回。**

**三元组合的完整风险画像(第57条，逐日真实净值)**：CAGR 12-18%（三段区间），日频Sharpe 1.2-1.7，真实最大回撤-10%到-25%——2/3区间里组合回撤比任何单一腿都浅，是这次会话里唯一一个从统计显著性到真实风险控制都自洽的结果。

**如实的结论**：目前没有一个配置能说"拿去实盘、有统计上站得住脚的把握"证明存在新edge。动量+价值+低波动三元组合是所有测试过的方向里证据最扎实的一个——大概率不比市场差，真实回撤也控制得住，值得作为风险管理工具考虑（分散化效应是真实的、有机制解释的），但不能当作"找到了新的alpha来源"去宣传。如果一定要选一个配置，这个三元等权组合是目前最站得住脚的选项，但风险认知要清楚：这更像是"几个中等质量信号凑在一起、降低了噪声、大概率跟市场打平或略胜"，不是"发现了确凿的超额收益来源"。

**两个重要的额外警示（第60/62条）**：①三元组合是从"价值单独→加动量→加低波动"三次迭代改进出来的，不是三个独立候选，天然比一次性测试更容易过拟合；②用2004-2009(含2008金融危机)对经典动量+低波动两条腿单独测试，发现分散化效应在真正的系统性危机里几乎完全失效（相关系数从平时的0.1-0.27飙升到0.73，组合回撤跟SPY自己崩盘的幅度几乎一样深）——这套组合没有证据表明能在真正的信用危机中提供保护，"分散化"不是免费保险。

**真正跳出股票资产类别之后的发现（第64/65/66条）**：换行业/市值/国家的股票内部分散化全部失败（国际市场ETF跟SPY相关系数高达0.71-0.89，比美股内部任何因子组合都高，2008年危机中甚至比SPY自己跌得更深）；但**债券(TLT/IEF)是真正的例外**——3/4区间跟SPY负相关(-0.35~-0.56)，2008年危机里60/40股债组合回撤只有SPY的一半左右；唯一的问题是2022-2026加息周期里这个负相关关系反转，60/40反而跑输纯SPY。用国债收益率趋势动态调整债券敞口（加息环境降低债券仓位）解决了这个问题——四段区间CAGR全部提升，2022-2026这段(静态配置失效的那段)回撤也同步改善。**这是这次会话"寻找真正分散化来源"这条线索目前证据最扎实的结果，机制清晰(利率风险管理)、不依赖迭代拟合，比动量+价值+低波动三元组合更值得信赖。**

**最终推荐配置（第67条）：三元股票组合 + 动态债券对冲层**。把第55条的三元股票组合当股票敞口、叠加第66条的动态债券配置(默认60/40，加息环境降到90/10)，三段完整数据区间测试：2009-2014(Sharpe 2.689)和2014-2020(Sharpe 1.758，回撤从-25.09%压到-13.71%)两段CAGR/回撤同步改善或打平，2022-2026这段CAGR有所牺牲(12.42%→8.08%)换取小幅回撤改善。**如果现在要从这次会话所有工作里选一个最终交付物，是这一条——不是发现了新alpha，是把几个真实存在的效应组合成一个逻辑自洽、经过多区间压力测试(包括2008年真实危机)的资产配置框架。**

用文献默认值看起来相当可信，但用这次会话自己的真实Sharpe离散程度(经验估计的标准差是默认值的两倍多，因为这次测试的策略五花八门、离散度天然更大)重新算，置信度大幅下降——宽口径下观测到的Sharpe几乎不比"测348次噪声里挑最大值"更好。**如实的结论：不能再说这个配置"证据扎实"，更准确的说法是"这个数字对‘应该用多窄的口径衡量搜索强度’这个假设极度敏感，诚实的答案是一个从24%到92%都有可能的区间，不是一个确定的高置信度结论"，这跟前面所有"三段区间全部显著"式的表述放在一起看，需要打一个大折扣。方法局限：窄口径本该用更小的、只属于那条搜索线索自己的标准差，但没能从文本里可靠地单独提取出来，所以窄口径这里用的是全项目标准差，是偏保守(会低估真实置信度)的近似。**

**【第504条，框架级大修大补：增强型指数化(Enhanced Indexing)，新引擎+诚实的中性结果】**把当前"挑几十只票、脱离基准"的因子押注模式，换成文献有实证支持的"标普500市值权重打底+现有因子分数(价值/低波动/动量)小幅超配减配+跟踪误差约束100-200bp"模式(Cremers & Petajisto 2009 / Petajisto 2013)，新增 `enhanced_indexing.py`(市值权重=价格×SEC点位时间shares + 三因子tilt + TE优化器)。2022-2026段头对头验证(旗舰=第377/383条推荐配置，本项目引擎重算)：beta从0.31往1拉但只到**~0.90**(价值+低波动tilt本身偏防御)，上涨周胜率 20.7%→32.2% 上升，但下跌周防御 86.2%→70.7% 让渡，综合胜率 48.2%→49.4%(≈50%没显著超过)，信息比率vs自建基准-0.11、vs SPY周超额Sharpe-0.27(block bootstrap P(≤0)≈75%)——tilt+换手成本吃掉全部超额，**不是净增益，甚至略跑输基准/SPY，跟用户事前预期完全一致**。TE精确命中100-200bp带(实现1.1%/1.6%/2.1%)。实现中发现sec基本面缓存有单条shares比正常值大~1000倍的坏数据(如PKG)，本引擎加了median护栏；现有value腿用同一份shares算P/E会把坏值票screen掉(可生存)，未在本次范围内修。**结论：增强型指数化在本项目数据上只测得了"把beta从0.31拉到0.9、用下跌周防御换上涨周参与"的暴露控制工具价值，不是净增益alpha来源，不建议取代旗舰组合；引擎保留为已实现的框架级探索(数据受限：仅2022-2026段有点位时间正确的市值，2009-2014/2014-2020无法忠实测试)，详见第504条。**

## 已知限制

- 免费数据源（yfinance）财报日期接口在标普500全量并发请求下失败率较高（约一半票拿不到财报日期），失败的票默认不做财报避让（fail-open），不影响整体运行但那部分风控形同虚设。
- 止损模拟基于日线数据，实际盘中价格路径可能不同，模拟的止损成交价是理论值。
- 交易成本假设双边0.3%固定值，没有随持仓规模/流动性变化的滑点模型，仓位放大后实际成本可能更高。
- `SECTOR_MAP` 依赖 `sp500_universe.json`，这个文件不会自动更新，标普500成分股变动后需要重新跑 `build_sp500_universe.py`。
- **生存偏差：已修复并量化，影响远超预期**（见"验证结论"第27条）。用点位时间正确的554只股票池（53只找回的被剔除票+动态每周成员过滤）重新跑5年回测，Sharpe从1.30跌到0.02（95%置信区间跨0），CAGR从37.15%跌到3.20%，跑输SPY基准。**README里任何早于本条修复、引用37.15% CAGR/1.30 Sharpe的数字都已经过时，不能再作为这套系统真实表现的依据**——`run_survivorship_bias_fix_validation.py` 里的结果才是当前最可信的估计。修复后仍有残余局限：39只已并购/私有化退市的票数据本身不存在，找不回来；纳入/剔除日期依赖Wikipedia外部数据，可能有个别记录误差；这些残余偏差方向不明确（不一定还是让结果偏乐观），量级也远小于已修复的部分。
- **并行执行噪声：已修复**（见"验证结论"第32条）。`n_workers>1` 并行回测在修复前不是确定性的（BLAS/OpenMP线程数不受 `xgb_n_jobs=1` 约束，8个worker各自内部又开满线程池，浮点求和顺序竞争导致同一份代码同一份数据跑两次结果不同），已经在 `backtest.py` 开头设置 `OMP_NUM_THREADS=1` 等环境变量修复，修复后验证过并行跑两次结果bit-for-bit一致。**这条修复之前的所有全量验证数字（包括第27条的头条数字）绝对值都应该打上"可能有若干个百分点执行噪声"的折扣，方向性结论不受影响（效应量级远超噪声量级）；这条修复之后的全量验证数字不需要再打折扣。**
